# 分类加载与节目表状态调整

## 已确认的开销

使用本机 SQLite 的一致性备份做隔离测试，原库有 22,309 条线路。测试不启动播放器，不上传频道、收藏或源地址。

旧的国际分类路径会查询 11,788 条候选线路，完成列表身份、分类元数据和备用线路索引约需 12.16 秒。所选国家的筛选发生在查询及身份整理之后。列表与备用索引重复查询了同一批身份和合并信息。首页的频道表监听也会读取整张表，初始订阅与显式启动加载还会重复发起刷新。

启动读取收藏 ID 时会先执行全目录收藏关系校对，旧路径约 7.17 秒。此工作与当前分类的显示没有先后依赖。

## 实现范围

- 简洁模式公共分类直接按已审计分类路径查询；国际频道按所选国家查询。国家菜单使用分组计数，保留全部国家入口，国家别名合并规则不变。
- 高级模式保留私人来源的旧分类逻辑，先筛选国家，再整理当前范围的身份信息。高级模式下无结构化分类的私人源仍可能需要较大的候选查询，不能将公共分类的测量结果套用到该路径。
- 列表和备用线路索引复用同一组已核实的身份、合并和公共 ID 元数据。完整服务身份的消歧上下文保持不变，大批身份计算放到工作 isolate。
- 最多缓存 4 个分类范围，同时合并相同范围的并发请求。目录、源、收藏和手动分类变化会失效相关缓存。旧请求不得写入新修订的缓存，过期分类结果不得覆盖当前选择。
- 频道表监听改用轻量失效事件；合并刷新通知，不再为监听物化整个频道表。收藏夹筛选直接复用已经读取的列表，避免二次异步查询及晚到结果覆盖新分类。
- 已存收藏先显示，历史关系校对延后到首屏绘制后执行，仍保留完整身份及事务保护。校对本身仍是全目录维护工作，耗时及数据库竞争没有算入下面的分类缓存命中时间。
- 普通播放界面移除全局 EPG 过期浮层。后台版本检查、断网重连、缓存和映射均保留。受服务器节目表影响的频道展开区域及节目表页面显示“暂无最新节目表”，私人来源与无映射频道不显示此状态。
- 设置中的“服务器节目表状态与许可”可查看覆盖截至时间、最近检查、下次检查与安全状态码；许可署名离线可用。此变更不产生新的节目数据，也不改变服务器采集任务。

## 测量边界

`tools/diagnostics/category_loading_benchmark.dart` 使用隔离的数据库备份和模拟首选项。单位为毫秒，属于本机 Flutter 测试环境的数据库及索引阶段，未代表各平台实机上的完整首帧、视频打开或网络耗时。

新路径的国家导航首次读取 118.0 毫秒，已有收藏读取 137.7 毫秒。保留的全目录历史收藏校对测得 9.30 秒，已移出首屏等待链。维护中的冷分类读取仍可能受到 SQLite 事务排队影响。

本地原始测量、分析和编译日志保存在仓库外的 `outputs/BobTV-category-20261101`，含私人数据的 SQLite 备份不会提交或上传。
