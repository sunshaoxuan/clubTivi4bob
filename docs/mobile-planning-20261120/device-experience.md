# 分设备交互与验收草案

日期：2026-11-20。配套 [开发计划](./README.md)。本文件描述目标体验，未表示已实现。v0.2 按用户要求统一 iPad/Android Pad 布局，手机改为频道抽屉；详细交互以 [手机 UI/UE 计划](./mobile-ui-ue.md) 为准。

## 1. 共同主流程

首次启动显示空资料库和“添加播放源”。用户输入 URL，应用识别列表或媒体清单，展示订阅名称、预计导入数量及需要的权限，再完成导入。解析失败保留用户输入，提供可理解的原因和重试入口；不得将任意错误伪装成空频道列表。

已有订阅时进入可选择频道的播放首页，不默认自动播放。手机通过“选择频道”或“频道”按钮打开抽屉，平板通过竖屏下方或横屏右侧频道区选择；收藏和最近播放均保留来源身份。节目单缺失不阻断播放。订阅刷新显示状态、上次成功时间和失败原因，失败保留最后有效数据。

删除订阅前说明对本地频道、收藏引用和下载数据的影响。多个源的用户备注及收藏不能因另一个源刷新而被覆盖。更改列表地址或登录凭据后，旧任务取消或隔离。

## 2. iPhone

| 页面或行为 | 目标 |
| --- | --- |
| 导航 | 播放页提供明确“频道”按钮；沉浸播放隐藏常驻底部导航，来源及设置从管理入口进入 |
| 频道 | 竖屏从下向上、横屏从右向左呼出抽屉，最多两列、上下滚动，窄屏或大字体时一列 |
| 分类 | 大触摸按钮；在抽屉内切换至筛选内容，选择后点“应用”，避免叠加弹窗 |
| 播放 | 点击频道直接开始主播放；先保证单解码器，首版不默认同时运行静音预览 |
| 播放详情 | 竖屏视频在上，节目单和线路在下；全屏时控制层可显隐 |
| 横屏 | 播放优先，频道继续使用右侧覆盖抽屉，减少工具行占高，保留核心控制 |
| 系统交互 | 支持安全区域、系统返回手势、键盘遮挡、文字放大与 VoiceOver |
| 生命周期 | 来电、耳机变化、锁屏、后台及返回前台按明确策略处理，防止双重音频和黑屏 |

是否启用后台音频默认行为，需在 P1 真机验证后确定。用户退出播放页与返回资料库的行为必须明确，避免无提示继续播放。

## 3. iPad

| 页面或行为 | 目标 |
| --- | --- |
| 竖屏 | 与 Android Pad 相同，播放器在上、频道区在下，视频保留比例，频道区独立滚动 |
| 横屏宽窗口 | 与 Android Pad 相同，播放器在左、频道切换区在右 |
| 中等窗口 | 先按方向采用上下或左右布局，确保频道文字和触摸区域可读 |
| 窄窗口 | 频道切换区变为与手机相同的抽屉，功能仍然可达 |
| 状态保持 | 旋转、分屏和窗口调整后保留来源、频道、搜索、滚动位置及播放会话 |
| 输入 | 触控主路径完整；键盘搜索和返回、焦点、指针操作作为平板验收项 |
| 多画面 | 后续阶段再评估设备性能、音频归属及同时解码上限 |

iPhone 与 Android 手机共用抽屉交互，iPad 与 Android Pad 共用平板布局；业务模型和分类规则共享。通过设备交互类型和可用窗口共同决定展示，手机横屏不自动启用平板常驻双栏。

## 4. Android 手机与现有平板

建议将 Android 手机纳入本轮。工程已有 Android 入口、窄窗口组件和播放能力，新增成本主要在手机交互、网络策略与系统生命周期，需要实测后量化。

手机复用 iPhone 的播放页与随方向变化的频道抽屉，独立处理 Android 返回行为、系统栏、键盘、PiP 和权限。返回顺序按键盘、搜索或分类子模式、抽屉、全屏、页面逐层处理。现有显式退出条在手机是否占用过多空间列入原型评估，暂不删除既有功能。

Android 平板作为 iPad 的布局基线，保留现有功能并共同改进触摸分类；TV 保留遥控器与焦点交互，不能因共享触控布局而改变。折叠屏先覆盖窗口变化与展开收起，跨折痕专门布局后续评估。

## 5. 首版验收矩阵

以下尺寸为候选逻辑视口，不代表已有设备；P1 核实实际库存和系统版本后补具体型号。

| 设备组 | 至少覆盖 |
| --- | --- |
| iPhone | 约 320/375 宽的小屏、约 390 至 430 宽的常规屏；抽屉、一列与两列、横竖屏、安全区域与键盘 |
| iPad | 小型和大型窗口、全屏、窄多任务窗口及连续调整大小 |
| Android 手机 | 约 360 宽和约 412 宽；频道抽屉、触摸分类、手势导航、返回、键盘、后台返回 |
| Android 平板 | 现有 640×360、1024×600 等回归视口，至少一台实际平板 |
| 既有平台 | macOS/Windows 主要布局，Android TV 焦点操作，当前发行版启动和目录行为 |

共同验收：首次安装为空；合法测试源导入成功；HLS 单流与列表识别正确；无 EPG/无台标可播放；令牌过期提示准确；空列表、错误密码、断网、重定向和列表变化有结果；失败刷新保留旧数据；删除后不复活。

播放验收：支持的测试编码先列清单；首次出画面、切台延迟、内存、温度和耗电分别记录。候选持续播放至少 30 分钟，并测试至少 20 次切台和连续旋转；这些是首轮采样要求，正式性能阈值在 P1 基线测量后确定。记录网络和码率，避免把源故障归因于应用。

模拟器负责布局与流程，真机负责解码、音视频同步、发热、系统中断和原生能力。测试报告区分“静态检查”“自动化通过”“模拟器通过”“真机通过”，不互相替代。

## 6. 后续增强

PiP、AirPlay、DLNA、录制、后台同步、云收藏和多画面逐项验证平台实现与需求。首版不在界面中展示尚不可用的开关。四种既有语言继续覆盖，中文长名称、其他语言较长文案和字体放大需要检查截断、按钮可达性。
