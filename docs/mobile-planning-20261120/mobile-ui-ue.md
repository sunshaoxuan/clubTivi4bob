# 手机频道抽屉 UI/UE 计划

日期：2026-11-20，日本时间。状态：交互草案 v0.3，仅文档与静态低保真图，未实现界面。已提供 [低保真图 v0.2](./wireframes/README.md)，包含竖屏、横屏、频道抽屉与分类筛选。

## 1. 已确定的方向

依据本轮用户要求：iPad 和 Android Pad 采用相同的布局结构：竖屏上方播放、下方频道，横屏左侧播放、右侧频道；iPhone 和 Android 手机共用手机交互结构。手机把平板右侧常驻的频道区改为按需呼出的抽屉，频道最多两列、上下滚动。分类操作按手指触控重新设计。

平板保持当前播放器在左、频道切换在右的基本关系。手机播放页默认收起频道抽屉，腾出观看区域。平板窄多任务窗口在内容容纳不下时，也可以使用相同的抽屉结构。手机横屏仍以抽屉为主，不因窗口变宽自动切成平板常驻双栏。

以下尺寸、默认行为和文案是本轮设计建议，待低保真评审后确定。共用布局结构允许 iOS 和 Android 保留各自返回、系统栏、焦点及辅助功能行为。

## 2. 手机播放页

播放页围绕视频组织，保留“频道”明确按钮。轻触视频显示控制层，控制层包括播放暂停、当前频道、频道抽屉入口、全屏与更多。频道入口在控制层右下方，避开进度或直播状态、系统手势区域；不能只靠屏幕边缘手势寻找。

竖屏页面：视频保持原始比例，上方或播放器内显示频道名称，下方可显示当前节目和必要操作。手机首版不把完整节目单、源管理和复杂设置同时挤进播放控制层。横屏全屏：视频占主要区域，频道抽屉覆盖在右侧，底层视频尺寸不因抽屉反复改变。

未选择频道时不自动播放，不弹抽屉抢占首次进入；显示“选择频道”入口。导入成功后可自动打开一次频道抽屉，便于用户选择第一条。没有任何订阅时显示“添加播放源”的独立空状态。

播放页之外保留来源、收藏与设置管理入口；进入沉浸播放后隐藏常驻底部导航。收藏入口与抽屉内的收藏快捷筛选可以指向同一资料，不复制数据。

## 3. 频道抽屉结构

竖屏采用从底部向上呼出的抽屉，横屏采用从右侧向左呼出的抽屉。分类模式沿用当前方向的同一个抽屉容器。展开时视频继续播放，抽屉外区域有适度遮罩，视频仍可辨认。遮罩区域只承担关闭抽屉操作，防止透传触发播放手势。抽屉展开后不自动计时关闭。

自上而下排列：

1. 固定标题行：“频道”、当前筛选数量、关闭按钮。
2. 工具行：搜索入口、分类按钮和当前来源摘要；短横屏可合并为一行工具区。
3. 快捷范围：“全部 / 收藏 / 最近”，互斥切换，在当前来源范围内生效。
4. 已选分类摘要，显示关键路径与“清除分类”；未选择时省略，避免固定占用高度。
5. 频道内容区：最多两列，按行排列，单一纵向滚动区域。
6. 有需要时显示的底部状态行：更新失败、重试或回到正在播放，不常驻大工具栏。

标题、必要工具和关闭入口固定，频道区独立滚动。顶部筛选在短横屏压缩为“范围 + 分类”工具行，减少展示项，不缩小触摸热区。分类展开后采用独立内容模式，避免在抽屉中继续堆叠工具行。

## 4. 两列与抽屉尺寸

| 项目 | 低保真候选规则 |
| --- | --- |
| 竖屏范围 | 抽屉铺满可用宽度，默认顶部位于视频下沿附近，保留上方视频；按内容和键盘需要可上拉扩展，顶部提供拖动条 |
| 横屏宽度 | 优先约 360 至 420 逻辑像素，同时为抽屉外区域保留关闭空间；空间不足时收缩 |
| 列数 | 宽度和文字大小允许时两列；窄窗口或大字体降为一列，任何情况下最多两列 |
| 两列候选下限 | 卡片可用宽度至少约 132，左右边距各 12、列间距约 8；实际以文字和触摸验收确定 |
| 高度 | 填满可用高度，顶部、底部避开系统安全区域；键盘出现时内容区随可用空间调整 |
| 滚动 | 列表仅上下滚动，不使用频道横向分页或每列各自滚动 |

例如竖屏可用宽度 360 时，抽屉铺满宽度，按左右边距各 12、列间距 8 计算，每卡约 164；可用宽度 320 时每卡约 144。文字或触摸空间不足时降为一列。数值为候选，不能用强制两列牺牲可读性。

## 5. 频道卡片与切台

卡片内容依次为台标和频道名称、正在播放的节目、当前频道或加载状态。台标缺失采用占位图；频道名最多两行，当前节目一行，完整信息在详情中查看。节目单缺失显示精简状态，不阻止选台。默认不放正在播放的视频预览。

整张卡片是切台热区。普通点按直接请求播放，不要求双击。正在播放卡片同时使用边框和“播放中”文字，不能仅靠颜色区分。收藏和线路管理放入明确的详情或更多入口，首版不在每张小卡片堆叠多个小按钮；长按可作为补充入口，不能是唯一入口。

建议的选台流程：点选后卡片立即显示加载状态；首帧可显示时自动收起抽屉，并保留筛选和滚动位置；播放失败则保留抽屉、标注失败并允许重试或换台。请求后候选超时为 8 秒，未就绪时显示可继续等待或换台的状态，最终阈值根据真实源基线调整。

连续点选时以最后一次选择为准，旧请求不得覆盖新频道状态。抽屉操作、搜索和筛选本身不切台。点按已播放频道可直接收起抽屉，不重建解码器。用户在加载期间主动关闭抽屉，关闭立即生效，切台结果在播放页反馈。

是否增加“切台后保持抽屉”偏好在低保真评审中验证，首版先采用首帧成功后自动收起的建议，不预先增加设置项。

## 6. 分类与筛选

分类采用大触摸目标，主入口显示文字“分类”和已选数量。避免照搬桌面多层细小按钮、悬浮菜单和横向文字跑马灯。

分类按钮切换抽屉内部的内容区，进入“筛选频道”模式。它占用当前抽屉，不叠加第二个侧抽屉或底部弹层。顶部保留返回与关闭，底部固定“重置”和“应用”。频道继续在背景播放。

筛选内容按来源、国家或地区、频道类别逐组纵向排列。只展示该订阅实际提供且能可靠映射的维度；无地理信息时提供“未分类”，不猜测频道归属。来源组表示订阅选择，分类组表示频道元数据，收藏与最近表示浏览范围，三者分别保存。

候选单选规则：每一维度单选，可选“全部”；支持来源 + 地区 + 类别组合。层级分类先显示上级，选定后展示下一级；更改上级时仅重置失效的下级。具体层级对接现有目录模型，在原型中验证。

每组候选项采用带文字的块状按钮，按空间自动换行并纵向滚动，不强制左右滑动。较长分类名称可换两行。大分类列表提供组内搜索和展开更多，不把全部分类一次铺满首屏。选中项有勾选及文字状态。

选择期间只更新草稿与预计结果数；点击“应用”后回到频道网格，回到列表顶部显示结果。点击返回放弃未应用变更；点击“重置”清除草稿中的来源与分类，应用后生效。“清除分类”只清分类，保留来源、浏览范围和搜索词，文案与作用一致。

来源切换后重置不再可用的分类，并给予简短状态提示。全量清空使用“重置全部筛选”的独立入口，不能混用按钮名称。

## 7. 搜索、定位与状态记忆

搜索在抽屉内展开输入框，默认搜索当前来源、范围及分类中的频道，不进行未经说明的节目全文搜索。结果为零时显示当前条件，提供“清除搜索”和“重置全部筛选”的明确入口。

键盘关闭不关闭抽屉。清除搜索保留分类；取消搜索回到进入搜索前的条件和滚动位置。用户切换搜索词或筛选后不自动切台。

抽屉首次打开定位正在播放的频道；同一播放会话再次打开时恢复上次浏览位置，并提供“回到正在播放”按钮。当前频道不在筛选结果中时说明它被筛选隐藏，按钮可临时跳转到对应来源及未筛选范围；跳转前保存原浏览条件，允许返回。

来源、分类、范围与搜索条件作为浏览状态；当前播放频道作为播放状态，二者独立。列表更新时按稳定频道身份恢复位置，已删除的项目显示来源变化，不跳转到同名频道。

## 8. 开关、手势和系统返回

| 操作 | 结果 |
| --- | --- |
| 点播放页“频道” | 打开抽屉；播放继续 |
| 点抽屉关闭或外侧遮罩 | 关闭抽屉，保存浏览位置 |
| 竖屏拖动顶部把手 | 向上扩展、向下收起；频道区上下滑动优先滚动列表，避免误关抽屉 |
| 横屏抽屉向右滑动 | 作为收起的辅助方式，仅在非滚动交互区域起手时启用 |
| 分类模式返回 | 返回频道列表，放弃未应用草稿 |
| 搜索时系统返回 | 先收键盘；下一次返回退出搜索，再下一次关闭抽屉 |
| 普通抽屉系统返回 | 先关闭抽屉，再处理全屏和页面返回 |
| 播放页横竖屏变化 | 保留当前频道和播放会话；打开的抽屉在底部与右侧形态间切换，保持选择、条件、搜索词及列表锚点，不重启播放 |

不依赖系统右边缘滑动呼出，避免与 Android 返回及视频亮度、音量手势冲突。抽屉滚动与播放器手势隔离。播放器在抽屉关闭后恢复原来的控制层显隐策略。

## 9. 平板一致性

iPad 与 Android Pad 共用播放器在左、频道区在右的布局和分类组件。空间足够时频道区常驻，选台后保留频道区；两列频道限制针对本轮手机抽屉，不自动约束现有平板卡片密度。

平板进入窄多任务窗口时，使用手机同款抽屉和触摸分类，防止强挤双栏。恢复宽窗口时将相同浏览状态放回右侧区域，避免出现两个频道面板或两个播放器。平板分类可使用相同的区域内筛选模式，保持命名、选择规则和重置规则一致。

## 10. 触控与无障碍

本项目候选统一触摸热区至少 48×48 逻辑像素，原生层分别核实 pt 与 dp 的换算。分类按钮间隔建议至少 8 逻辑像素。这里采用 Android 推荐 48 dp 及 Apple 常规建议 44 pt 作为设计参考，数值不等同于最终视觉图标大小。

抽屉打开后辅助功能焦点移到标题，焦点限制在抽屉，背景视频不参与遍历；关闭后回到“频道”按钮。选中、加载、失败和结果数量需要可朗读状态，加载提示避免高频重复播报。支持系统减少动态效果和大字体，一列降级后仍保留全部操作。

采用现有 BobTV 颜色与识别体系，先确定信息层级和对比度。关闭按钮、分类、来源和播放控制不只依赖图标表达。

## 11. 文本线框

以下为结构示意，不代表最终比例、颜色或已实现界面。

手机竖屏，抽屉关闭：

```text
┌──────────────────────────┐
│ 当前频道                 │
│                          │
│          视频            │
│                          │
│ 播放   全屏   [频道]     │

│ 节目详情与必要操作       │
└──────────────────────────┘
```

手机竖屏，底部抽屉展开：

```text
┌──────────────────────────┐
│         视频继续播放     │
│                          │
├─────────拖动条───────────┤
```

手机横屏保留从右向左覆盖进入的抽屉；返回时按相反方向收起。竖屏的分类筛选在底部抽屉内部切换，保留顶部视频。上拉扩展是待评审建议，初始抽屉开合方向已按用户要求确定。

## 12. 进入实现前的设计交付

先形成以下低保真页面和操作串联，再据此调整尺寸和默认行为：

- 手机竖屏播放、横屏全屏、抽屉开关和两列频道。
- 分类选择、长分类名、大量分类、来源切换和应用筛选。
- 搜索输入、键盘占用、零结果、一列大字体和窄屏。
- 切台中、成功关闭、失败保留、重复点选与主动关闭。
- iPad/Android Pad 宽双栏与窄窗口抽屉之间的转换。

原型评审重点：单手能否找到频道入口；常用分类能否在合理触摸次数内到达；开启抽屉是否遮挡关键字幕；短横屏是否还看得到完整频道卡；能否在不打断播放的情况下查找频道。先以典型任务记录点击次数和误触位置，再确定最终指标。

应用代码、服务器和资源包协议实现继续等待设计阶段完成，不因本文件新增而提前启动。
