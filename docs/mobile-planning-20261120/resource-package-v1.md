# BobTV 自定义资源包 v1 草案

日期：2026-11-20。状态：供设计审查，尚未实现，也未冻结字段。

## 1. 定位

定义可由任意兼容服务器产生的数据格式。用户手动添加地址，客户端读取清单并同步资料。相同数据在不同主机采用同一解析和展示路径；不以特定域名触发隐藏能力。应用支持的能力随应用提交，自定义资源包仅供应数据。

第一版建议使用 HTTPS JSON 清单，必要时允许 gzip 内容编码。批量图片压缩包留作后续可选能力，先减少解压路径与资源限制的复杂度。`.bobtv` 可以作为文件扩展名，网络传输以内容结构与版本字段识别。HLS、M3U、资源清单分别识别，扩展名不作为唯一判断依据。

## 2. 建议的数据结构

| 字段 | 用途 |
| --- | --- |
| `format` | 固定协议标识，例如 `bobtv-resource` |
| `schemaVersion` | 协议版本，首版为 1；不支持的主版本明确拒绝 |
| `id`、`name` | 提供方声明的资源标识与显示名称；本地订阅仍使用独立身份 |
| `revision` | 不透明的快照版本，用于判重，不默认用字符串大小判断先后 |
| `generatedAt` | 带时区的生成时间，仅用于展示和诊断 |
| `refreshAfterSeconds` | 建议刷新间隔，客户端设置合理上下限 |
| `channels` | 稳定频道 ID、名称、分组、台标地址、EPG 引用及线路数组 |
| `routes` | 每条线路稳定 ID、播放 URL 和明确支持的请求参数；可嵌入频道对象 |
| `epgSources` | XMLTV 等已支持数据源与频道身份映射 |

每个字段定义长度、数量、可选性和未知字段策略。未知可选字段忽略；缺少必填字段报错。频道 ID 必须在同一订阅内唯一。客户端身份采用本地订阅 ID 加远端频道 ID，防止两个提供方声明相同资源 ID 时污染收藏。

首版全量快照优先。增量删除与修订冲突等协议在全量同步稳定后增加。暂不支持任意模板语言、脚本、插件、动态库、Flutter 补丁、可执行命令或远程导航定义。

## 3. 同步事务

用户添加地址后先下载并校验格式、数量、资源引用和协议版本，显示导入摘要，再写入订阅。刷新使用 ETag 或 Last-Modified 等已有 HTTP 机制；服务端不支持条件请求时按本地节制策略拉取。

校验完成后，以数据库事务应用完整快照。远端数据与用户收藏、备注分开保存。刷新失败、下载取消或进程退出都不替换最后有效快照。相同订阅只允许一个有效刷新任务；删除或修改订阅时旧任务结果不得再次写回。

源的频道被删除时，收藏引用可以保留为“来源已移除”，由用户决定删除；不得静默关联到另一个同名频道。已有播放会话采用已解析的线路，列表刷新不主动打断播放，鉴权过期时提示重新验证。

前台定期同步加手动刷新作为首版保证。后台由系统调度，界面不承诺固定周期完成。失败采用退避并遵守 Retry-After，多个订阅的网络任务有并发上限。

## 4. 网络与隐私边界

默认使用 HTTPS，用户主动添加的 HTTP 和局域网来源单独制定连接策略并核实 iOS ATS 配置。避免为方便而无限制放开全局网络安全设置。

凭据尽量通过单独授权配置传递，敏感值写入平台安全存储；日志不记录完整 token、用户名密码或带凭据的 URL。请求头使用明确白名单。跨主机重定向不携带原主机凭据。清单和外部图片请求同样处理这一边界。

允许用户主动连接局域网服务器，但清单不能无限制请求其他本地地址或设备管理端点。对于清单内跨来源引用，定义可接受的目标、提示和请求限制；不通过 BobTV 生产服务器代取任意用户地址。

对压缩前后大小、频道总数、嵌套层级、字符串长度、下载时限、重定向次数和图片尺寸设置上限。具体值由 P1 数据采样决定，超限时明确失败。未来增加 ZIP 时还需防路径穿越、符号链接与解压膨胀。

SHA-256 用于完整性检测。由同一不可信来源同时提供内容和摘要，不能证明发布者可信或内容获授权。签名是可选扩展，信任模型另行定义，避免把开发者自营服务器作为唯一可用源。

## 5. 兼容性验收

准备两个不同主机的自有授权测试服务，输出同一协议，验证标准导入和刷新路径一致。使用最小包、大包、重复 ID、未知版本、错误类型、失效图片、损坏 gzip、超限响应、鉴权过期、取消、断网和删除中刷新等样例。

协议的完成标准包括：字段规范、可复用示例、错误码与用户文案、兼容策略、同步事务测试和审查可用测试源。协议与 M3U 的导入结果进入同一领域模型，避免形成只支持某一家服务器的另一套播放器业务。

## 6. 审核说明

提审文档说明下载内容、解析方式、刷新行为及全部能力，并提供有权使用的样例。自定义格式不赋予内容授权，也不能作为审核后新增隐藏功能的通道。

依据：[Apple App Review Guidelines 2.5.2、2.5.19、5.2](https://developer.apple.com/app-store/review/guidelines/)，查阅于 2026-11-20。该规则未要求使用 M3U；协议采用自定义格式不代表具体实现自动满足所有要求。
