# BobTV 1.1.13

All seven platforms use **1.1.13+108**: Windows x64/ARM64, macOS Intel/Apple Silicon, and Android ARM32/ARM64/x64.

- Isolate macOS update downloads, status, startup checks, skipped versions and rollback records by the canonical installation path. A test build or another BobTV copy cannot block the installed application's updates.
- Adopt a matching legacy pending update under a lock, retaining the original rollback bundle and creating fresh startup evidence for the new process. Leave unrelated legacy installations untouched.
- Preserve obsolete or unsafe state for inspection, refuse cross-installation state access, and protect an installer that is still running.
- Match startup health to the installation, running version and process. A stale PID receipt no longer ends the waiting period prematurely. A delayed monitor cannot clear a newer candidate.
- Confirm a healthy startup while the app remains running. Failed startup retries and three-failure rollback remain active for the owning installation. Historical backups remain retained.
- Retain the country/region normalization, top-level Other category, separate country TV/radio branches and background classification from 1.1.12. No application-defined daily AI request quota is introduced.

Already-blocked older clients execute their old updater before downloading new code. If that older updater cannot proceed, use the new DMG to replace BobTV once. The new application's first launch isolates and reconciles update state without clearing favourites, providers, guide data or credentials.

macOS applications remain ad-hoc signed, with separately publisher-signed update ZIPs. Apple Developer ID signing/notarization and trusted Windows Authenticode signing remain unavailable. Android retains its existing publisher certificate. Package validation does not imply physical ARM desktop or Android playback validation.
