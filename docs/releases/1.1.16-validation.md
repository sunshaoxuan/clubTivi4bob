# BobTV 1.1.16 validation

Version: `1.1.16+111`. Application source and tag:
`67ce08cd4e4b85d9cc31e55e4dd05d9bdb1b4bd1`.
All seven platform packages are rebuilt from that application commit.

## Channel and regression validation

- Category/favorite subsets now resolve every route of an authoritative catalog
  identity before calculating presentation keys. A new regression failed before
  the correction and passed afterward, including inconsistent route labels,
  favorite expansion and cross-category removal.
- National overview/genre membership grouping remains covered across 36
  combinations, with country, region, UHD, guide, radio and manual boundaries.
- A read-only backup of the installed database replayed 11 First Theater favorite
  records as one card. No live favorite or source rows were rewritten.
- Full Flutter suite: 857 passed, 22 environment-gated skips. Windows focused
  suite: 223 passed, five skips. Website template suite: six passed.
- Focused static analysis reported no errors or warnings and 12 existing style
  informational findings outside the new database block.

## Packages and signatures

- macOS Intel/Apple Silicon: 128 native files per architecture, strict application
  signature checks, version plists, DMG verification and publisher-signed ZIPs.
  The application runner and Dart payload are freshly compiled.
- Windows x64/ARM64: 208 and 203 native PE files validated, respectively, with
  matching executable/Setup versions, pinned native runtime files, archive payloads
  and every bundled updater asset. Windows CNG accepted both actual Setup
  publisher signatures and rejected tampered/malformed inputs.
- Windows source fidelity: 1104 tracked files verified. 1102 are exact byte
  matches; two installer/test scripts receive a UTF-8 BOM for PowerShell 5.1.
  Their source text is unchanged. The final check ran after builds and tests.
- Android ARM32/ARM64/x64: embedded version/base build, signing certificate,
  architecture/native libraries, integrity, publisher certificate and hashes
  passed the seven-platform release alignment gate.
- Native FFT inputs remain locked to the verified 1.1.14 dependency hashes. APK
  native libraries match those archives; macOS uses the common native source.
  No physical-device playback or new seven-platform native signal acceptance is
  claimed for this maintenance release.

## Windows test-environment recovery

- The first interactive rollback fixture could not increment its counter because
  the session's shared updater mutex was unavailable. An isolated session-zero
  run of the unchanged rollback code passed three-failure rollback and healthy
  startup reset. Existing application/update processes were preserved.
- Session-zero CNG verification stalled. Only its two positively identified
  fixture processes were stopped. Original logs and terminal status are retained.
  Real Setup CNG verification then passed in the interactive session.
- Managed-update fixtures used separate validation copies with only the mutex
  namespace changed to a test-specific name. Crypto checks and actual installer
  bytes were unchanged. Cancellation, explicit retry, protected rollback and
  failed-install recovery passed, with installer launches mocked.
- The progress-window fixture initially hit transient status-file replacement
  contention. Its status writer was given the same bounded I/O retry policy
  already present in production. All phase/launch guards, white controls and
  native close checks then passed. This is a validation-only follow-up change;
  it does not change the published application payload.
- Original failure receipts and all recovery/overlay hashes are retained in the
  local release output directory. No initial failure is represented as a clean
  first attempt.
