# BobTV 1.1.17

All seven packages use **1.1.17+112** and the same frozen application source commit.

- Failed playback lowers the route's local rank. Exhausting a public channel's alternatives requests a persistent, channel-bound server recovery job.
- The server researches public web and GitHub sources. A replacement needs verified channel identity, media-use permission and successful decoding before atomic admission into the public catalog. Failed routes and audit history are retained.
- Running clients synchronize the catalog and retry a newly admitted route without restarting the app. Changing the selected channel cancels the previous local retry intent while server research continues independently.
- Manual sources, locked identities, route tombstones and private favorites remain protected. Clients do not search GitHub or upstream websites.

## Acceptance and limits

The native acceptance tool runs the production channel screen, player, recovery client and database synchronizer in isolated preferences and storage. Its server uses a separate catalog and self-generated audio-free video. It covers failure demotion, real server decoding/admission/publication, runtime catalog import, automatic native playback recovery and cancellation after a new selection. Fictional test channels never enter the public catalog. This controlled test does not establish that a replacement exists for any particular broadcaster.

Android physical-device testing is explicitly waived by the user for this release. Shared automated regressions, signed APK checks and architecture/version validation remain required. Windows ARM64 and macOS Apple Silicon packages receive build/package validation; this run's physical desktop hosts are x64.

Five Malaysian recovery targets had no admitted replacement at the pre-release baseline. They remain in the server's backed-off research queue; this release does not claim those broadcasts were restored.

macOS uses ad-hoc application signatures and publisher-signed update archives. Apple notarization and trusted Windows Authenticode signing are not claimed. Android retains its existing publisher certificate. Publication does not install or restart the user's running applications.
