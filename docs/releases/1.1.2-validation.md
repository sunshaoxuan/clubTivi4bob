# BobTV 1.1.2 validation

Target: `1.1.2+95`. Manual publication; GitHub Actions remain disabled.

## Application and server tests

- Flutter suite: 477 passed, eight conditional skips, with the real Python HTTP
  fixture enabled. Covers custom classification upload and import through two
  independent databases, complete nested paths, permanent route retirement,
  device-private favorites and update status.
- Website/API suite: 155 passed. Resource routing and OS/CPU download menus:
  seven JavaScript tests passed. Frozen Mac sender packaging: two tests passed.
- Targeted analysis of the changed category, identity, private-sync and retirement
  components has no issues. The large existing screens still have legacy style
  and unused-member warnings, without new compilation errors.
- Production primary and cndrp endpoints passed isolated private-favorite
  upload/restore, different-credential isolation, wrong-fingerprint rejection,
  idempotent retry, conditional reads and private no-store headers. The two test
  identities were removed afterward; no public channel data was changed.
- Nginx conditional-header forwarding was tested over production HTTPS, with
  syntax validation and a reload limited to the BobTV relay configuration.
- Server data and modified code were backed up before deployment. Existing
  catalog inventory, device registry and resource-node modules were retained.

## Native packages

- A fresh Universal macOS application was compiled with Xcode 26.3, then split
  into Intel and Apple Silicon variants. All 128 native files per variant passed
  CPU checks; current sender source was refreshed and deep strict signatures
  verified. Both update ZIPs have verified BobTV publisher signatures and both
  DMGs passed disk-image verification.
- Intel Mac renderer tests passed 20 live software-rendered disposal cycles
  (239 frames), 20 hardware-rendered cycles (228 frames), and the packaged Metal
  adapter with 500 callbacks. The post-exit update fixture passed three-failure
  rollback, healthy-start acknowledgment and concurrent-worker exclusion.
- Android ARM32, ARM64 and x64 APKs passed package identity, CPU, ELF alignment,
  archive-secret exclusion and publisher certificate verification. Minimum SDK
  remains 24 (Android 7), and ABI-specific version codes are 1095, 2095 and 4095.
- Windows x64 and ARM64 packages are being built on sunsx-pc, with isolated
  installer/Unicode-path/architecture checks. Final package and delivery results
  will be appended after those gates complete.

## Publication acceptance

Public release, download hashes and update-feed acceptance remain pending while
the Windows builds finish. Installed desktop applications are not restarted.

Physical Surface ARM64, Xiaomi Pad and Apple Silicon playback, Mainland China
throughput, native private-key restore on an installed app, and real user UAC
approval remain unperformed. Mac apps are ad-hoc signed without Apple Developer
ID notarization. Windows packages lack trusted Authenticode signing, so a first
browser download can still require a security confirmation. Packaging and
isolated updater tests do not constitute an upgrade of an installed application.
