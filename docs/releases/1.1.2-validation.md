# BobTV 1.1.2 validation

Target: `1.1.2+95`. Manual publication; GitHub Actions remain disabled.

## Application and server tests

- Flutter suite: 477 passed, eight conditional skips, with the real Python HTTP
  fixture enabled. Covers custom classification upload and import through two
  independent databases, complete nested paths, permanent route retirement,
  device-private favorites and update status.
- Website/API suite: 155 passed. Resource routing and OS/CPU download menus:
  seven JavaScript tests passed. Frozen Mac sender packaging: two tests passed.
- Targeted analysis of the changed category, identity, private-sync and retirement
  components has no issues. The large existing screens still have legacy style
  and unused-member warnings, without new compilation errors.
- Production primary and cndrp endpoints passed isolated private-favorite
  upload/restore, different-credential isolation, wrong-fingerprint rejection,
  idempotent retry, conditional reads and private no-store headers. The two test
  identities were removed afterward; no public channel data was changed.
- Nginx conditional-header forwarding was tested over production HTTPS, with
  syntax validation and a reload limited to the BobTV relay configuration.
- Server data and modified code were backed up before deployment. Existing
  catalog inventory, device registry and resource-node modules were retained.

## Native packages

- A fresh Universal macOS application was compiled with Xcode 26.3, then split
  into Intel and Apple Silicon variants. All 128 native files per variant passed
  CPU checks; current sender source was refreshed and deep strict signatures
  verified. Both update ZIPs have verified BobTV publisher signatures and both
  DMGs passed disk-image verification.
- Intel Mac renderer tests passed 20 live software-rendered disposal cycles
  (239 frames), 20 hardware-rendered cycles (228 frames), and the packaged Metal
  adapter with 500 callbacks. The post-exit update fixture passed three-failure
  rollback, healthy-start acknowledgment and concurrent-worker exclusion.
- Android ARM32, ARM64 and x64 APKs passed package identity, CPU, ELF alignment,
  archive-secret exclusion and publisher certificate verification. Minimum SDK
  remains 24 (Android 7), and ABI-specific version codes are 1095, 2095 and 4095.
- Windows x64 and ARM64 Setup installers and ZIPs were built on sunsx-pc.
  PE/AOT architecture, embedded version, refreshed sender and package checks
  passed. ZIP entries use normalized forward-slash paths.
- Isolated Windows installer fixtures passed desktop-shortcut enabled/disabled,
  Unicode installation paths, old-process waiting, Start menu policy and
  uninstall checks. Existing BobTV installations were not changed.
- Both actual Setup files passed BobTV P-256 signature verification with Windows
  CNG. Tampered and malformed fixtures were rejected, and the four updater
  scripts passed PowerShell parsing.
- Managed update fixtures passed cached-package verification, authorization
  cancellation preserving the old application and downloaded package, distinct
  retry requests, and rollback through the signed previous Setup. The actual
  elevated installer launch is mocked at this boundary; user UAC approval was
  not automated.
- The isolated native Windows progress window rendered successfully. Launch is
  disabled throughout pre-installation phases, and the ready button requests
  installation authorization rather than starting an uninstalled application.
  Its temporary interactive task was removed after the test.

## Publication acceptance

GitHub release `v1.1.2` is public, with 13 assets verified against local byte
counts and SHA-256 hashes. GitHub Actions remain disabled. Main branch source
is published at `48bcd2439be8cb9eed865e31d30a4ba094f17269`.

The primary mirror completed successfully at `2026-10-12 14:47:59 UTC`, logging
`Published 86 mirrored releases`. Website content deployment preserved the API
runtime byte-for-byte and backed up the prior content at
`/opt/bobtv/backups/website112-20261012T145405Z`. The service is active and the
temporary build-source archive has been removed from public assets.

All 12 localized page checks passed: homepage, downloads and diagnostics in
Simplified Chinese, Traditional Chinese, English and Japanese. Published copy
matches the release source, including new category creation, device-private
favorites, update progress and platform installation caveats. Browser visual
QA was not performed because a saved browser permission blocks this website.

Public delivery acceptance passed on both the primary site and cndrp:

- 14 latest-version feeds, covering seven OS/CPU combinations on both nodes.
- Four historical Windows Setup feeds, with matching installer size, SHA-256
  and publisher signatures.
- 18 manual range requests, each returning HTTP 206 and the requested bytes.
- 36 complete downloads across manual and update URLs, with matching byte counts
  and SHA-256 hashes. All 18 cache-node bodies subsequently reported cache HIT.

Metadata and range checks used ordinary public DNS. Complete-body checks used
the production HTTPS virtual hosts through a direct origin address and cache
host loopback, retaining normal TLS hostname and certificate validation.
Parallel reads encountered timeouts; after bounded reads, 35 bodies completed
and the remaining primary Android ARM64 update APK passed an isolated retry.
These results establish integrity and cache readiness, not consistently fast
delivery from every end-user network. Mainland China throughput is not measured.

Local machine-readable evidence is retained in the `outputs/BobTV-v1.1.2`
release directory, including GitHub assets, public delivery, localized pages,
private API isolation and deployment backups. Installed desktop applications
are not restarted by publication.

Physical Surface ARM64, Xiaomi Pad and Apple Silicon playback, Mainland China
throughput, native private-key restore on an installed app, and real user UAC
approval remain unperformed. Mac apps are ad-hoc signed without Apple Developer
ID notarization. Windows packages lack trusted Authenticode signing, so a first
browser download can still require a security confirmation. Packaging and
isolated updater tests do not constitute an upgrade of an installed application.
