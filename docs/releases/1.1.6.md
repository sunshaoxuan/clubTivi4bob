# BobTV 1.1.6

Build: `1.1.6+99`. Manual release for Windows, macOS and Android.

## Changes

- Add one shared native-player ownership registry for main, preview, warm,
  replacement and multi-view players. Duplicate disposal shares one operation;
  a caller timeout does not discard an unfinished native cleanup.
- Route desktop close, application quit and update-exit paths through an awaited
  cleanup barrier. Detach video views before draining players and callbacks;
  failed cleanup keeps the engine alive with a retry action. Add auditable
  exit reasons and native macOS close-event records.
- Release the native close veto only after platform-requested cleanup has
  completed, allowing Windows to finish its exit acknowledgement normally.
- Add a shared, server-owned EPG client that periodically checks the BobTV
  primary or cndrp version endpoint while the app is running. Foreground and
  network recovery trigger additional checks. An unchanged version avoids
  downloading and parsing the full programme snapshot.
- Verify snapshot hashes and import programmes transactionally. Invalid or
  interrupted updates preserve the last valid cache. Expired or fallback cache
  state is visible. The legacy four-hour source throttle does not block the
  new server version checks.
- Refresh channel-card schedules, current/next programmes, the guide and
  fullscreen EPG when the local EPG database changes. EPG synchronization does
  not call player-open operations or reset the guide's scroll position.
- Preserve manually locked mappings, personal sources and private data. Public
  catalogue identity hashes prevent schedules being assigned to a changed feed.
  Source attribution is shown separately for server-owned data.
- Include the bounded, resumable server EPG discovery, structured-source
  conversion, recovery audit and atomic-publication implementation. The server
  timers operate independently of this Mac and the chat. Programme-data rights,
  exact feed identities and current/future coverage remain publication gates.
- Include the server route-state read isolation and public-route validation
  correction deployed after the Windows switching report. Network failure can
  still prevent a fresh retirement check; no offline relaxation of permanent
  route-retirement protection is included in this release.

## Programme availability and validation limits

The new client logic requires this first upgrade. Older clients do not gain
background EPG version checking through server changes alone. The new server
EPG manifest has no approved programme version at release preparation, with
zero verified public mappings. Existing client/private EPG data remains usable.
Source diagnostic counts are not public catalogue coverage.

Fixture tests cover two successive versions, checksum failure, rollback,
reconnection, manual/private isolation, source timeout/recovery and expired
HTTP-200 responses. Two real consecutive production publications, broad
verified alternative-provider activation and physical Windows/macOS/Android
EPG playback, reconnect and uninterrupted-audio acceptance remain incomplete.
This release does not declare the full EPG enhancement complete.

Native-player cleanup regressions passed on Windows x64 and Intel macOS,
including ten-minute main/preview playback, twenty create/dispose cycles and
safe exit with zero remaining players. These use an original raw-video/PCM
fixture with muted/null audio output. Audible audio, H.264 hardware decoding
and ARM64 physical-device acceptance are not established by those tests.

## Packages and updates

Windows x64/ARM64 Setup and portable ZIPs; macOS Intel/Apple Silicon DMGs and
publisher-signed update ZIPs; Android ARM32/ARM64/x64 APKs, Android 7/API 24+.
macOS dependencies currently require macOS 13 or newer. Windows has no trusted
Authenticode certificate; Program Files upgrades require administrator consent.
Mac packages use ad-hoc application signing without Apple notarization.
BobTV publisher update signatures are separate integrity checks. Android
installation requires system confirmation. Publication does not install over,
close or restart existing applications.

See [validation](https://github.com/sunshaoxuan/clubTivi4bob/blob/main/docs/releases/1.1.6-validation.md)
for package and public-delivery evidence and unperformed checks.
