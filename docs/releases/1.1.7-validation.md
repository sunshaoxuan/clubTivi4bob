# BobTV 1.1.7 validation

Target: `1.1.7+100`. Publication is in progress on 2026-10-17 JST.
Evidence is retained under `outputs/BobTV-v1.1.7/` and
`outputs/BobTV-route-performance-20261017/`.

## Verified before release packaging

- The targeted playback, preview, route ranking, retired-route and UI resource
  suite passed 41 tests. Eight strengthened immediate-preview tests passed again.
- Preview ownership reuses the existing decoder and controller. The buffering
  recovery gate and scheduled-frame wait were removed. Native audio handoff and
  retirement/superseded-request guards remain.
- The scoring repair was deployed to the main API only. Six public ranking and
  eight network-profile requests across main and cndrp returned HTTP 200.
  The largest relay ranking request took 4562.37 ms. No media probes or synthetic
  playback reports were submitted. The EPG API process was not restarted.
- Before the final immediate-preview revision, 130 client tests passed,
  including two real public snapshot imports with 8,766 channels and 9,604 routes.
  The backend scoring tests passed 29 cases. These are separate overlapping runs.

## Frozen-source validation

The first fully tested production source was
`8b1ee694cd9bcafe1c1c05a51c4c37d5461c6af5`. A subsequent Windows
authorization-polling fix is being frozen and rebuilt before publication.

- The complete client suite passed: 716 passed, 17 skipped.
- Scoring and localized release-template regression passed 20 backend tests.
- The native diagnostic target passed static analysis with zero errors.
- All three Android APKs passed package identity, ABI, version-code, publisher
  certificate, native architecture, alignment and archive CRC verification.
- A Windows native-library extraction left incomplete by an interrupted build
  was repaired only in generated build output, after verifying the upstream
  archive hash. Release source and installed applications were unchanged.
- Six authorization-polling regression cases passed, including a dead helper
  with each stale consent phase, old-request exit protection, explicit retry
  after cancellation, and preserving a completed receipt after normal exit.
- The isolated Mac native fixture passed explicit and platform exits, reusing
  the exact decoded preview player/controller. Native local-fixture transfer
  took 9,362 and 10,478 microseconds. These are internal transfer measurements,
  with null audio, and do not measure end-user network playback latency.
- The first hidden Mac fixture received a last-window termination request before
  reaching its preview-commit checkpoint. It was preserved as an interrupted
  test, followed by the passing visible-window runs above.

## Physical acceptance limits

No installed client is replaced or restarted. New-version measured switching
latency, audible continuity, long playback, and Windows ARM64, Apple Silicon and
Android physical-device acceptance remain pending. Existing lifecycle soak
evidence from 1.1.6 is historical and does not certify the new preview path.
The other Windows machine's authorization stall has not been reproduced on that
machine. Secure-desktop UAC approval requires human/device acceptance; mocked
consent boundaries do not establish a successful real UAC interaction.
