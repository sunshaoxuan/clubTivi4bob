# BobTV 1.1.7

Build: `1.1.7+100`. Manual release for Windows, macOS and Android.

## Playback and client workload

- Prefer the highest known score for the current network across the channel's
  candidates. Actual decoder failure advances to the next candidate. Unavailable
  scoring falls back to cached current-network observations.
- Remove parallel startup media probes. Advisory score refresh is bounded and
  does not require opening many candidate streams before starting playback.
- A decoded card preview transfers its existing player and video controller on
  the second click. No repeated route batch synchronization, buffering recovery
  timer, stability validation, cold reopen or scheduled-frame wait is added to
  that path. Native audio handoff still takes real processing time.
- Public names, categories, route ownership, order and reviewed EPG mappings come
  from the server. Remove browse-time AI submissions, public name-based
  regrouping, call-sign sorting, EPG name guesses and category-wide media scans.
- Preserve manual categories and EPG mappings, private sources, favourites and
  offline data. The original channel continues playing during preview loading.
- Retain server EPG import compatibility for licensed open-government data,
  explicit schedule gaps, exact stored identity bindings and network recovery.
  These changes do not add local programme discovery or generated schedules.

## Scoring service

The deployed scoring service separates quota accounting from the catalogue
writer and uses read-only ranking queries. This fixes the inspected SQLite-lock
503 path while preserving existing observations and rate limits. Server scoring
repair is already deployed; the client improvements require this new version.

## Validation and limits

Windows update-status polling now checks helper liveness before ignoring a stale
authorization receipt. A helper that has exited can no longer leave that path
displaying authorization indefinitely. This does not bypass Windows consent or
claim that every machine-specific authorization failure has been reproduced.
The existing update entry also shows the running version/build directly, even
when it reports that no update is available. This is static UI text and adds no
background discovery or processing.

Package, automated regression and public delivery evidence is recorded in
[validation](https://github.com/sunshaoxuan/clubTivi4bob/blob/main/docs/releases/1.1.7-validation.md).
Measured click latency, audible continuity and full playback acceptance on each
physical platform remain user/device checks. Automated tests do not establish
zero native latency or universal source availability. Broad autonomous EPG
source discovery and complete public EPG coverage remain unfinished.

No installed application is replaced, closed or restarted during publication.
Writable Windows portable and macOS installations apply verified updates after
exit. Windows managed installations use the existing authorized Setup workflow;
Android uses the platform package installer.

Windows packages do not have a trusted Authenticode certificate. Mac packages
use ad-hoc application signing and BobTV publisher-signed update archives without
Apple notarization. Existing macOS dependencies require macOS 13 or later.
