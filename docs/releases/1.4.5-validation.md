# BobTV 1.4.5 desktop validation

Published on November 25, 2026, Asia/Tokyo. Application source: `a8bceefc8726f62e43cb15c3e9a1ec99df10a835`, already on remote main before compilation. Public version is `1.4.5`; native update identity is `1.4.5+8`. Build 7 was retired before compilation when an obsolete website assertion was found.

Windows x64/ARM64 and macOS Intel/Apple Silicon were compiled from this source. Android and iOS packages were excluded; the three Android update feeds were preserved.

- Flutter casting and updater regression: 35 passed.
- Python AirPlay regression: 51 passed, no skips. The conditional FFmpeg remux and HTTP relay test used an isolated QA executable, with no audio device playback.
- Release template/alignment/finalization/updater checks: 21 passed. Mirror/delivery/finalization/updater checks: 19 passed. These selections overlap.
- Windows native helper startup, package architecture, AOT architecture and packaging checks passed in [workflow 45510368762](https://github.com/sunshaoxuan/clubTivi4bob/actions/runs/45510368762). x64 installer tests passed.
- macOS variants each passed architecture checks for 132 native files and strict code-signature verification. The frozen sender modules were rebuilt from the frozen source in the pinned Python 3.12 runtime. Intel helper startup, valid/corrupt updater handoff and observer replacement tests passed.
- All 12 public release files passed package alignment and checksum verification. GitHub asset digests matched the local files.
- The origin mirror completed successfully. Full hashes verified 14 origin files and six native-version compatibility aliases.
- Primary and secondary public endpoints passed 90 checks covering seven languages, all seven update feeds, release indexes and download ranges. Android primary feed values were identical to the pre-release baseline.

macOS uses the existing self-hosted signing profile with ad-hoc application signing and a publisher-signed update archive. Developer ID and notarization are not implied. Windows Setup and updater components carry BobTV publisher signatures; Windows Authenticode signing is not provided by this workflow.

LG WebOS physical playback, the reported channel-specific quality/stuttering problem, and physical ARM64 playback acceptance remain pending. Fixed-password AirPlay video receivers remain unsupported. AirPlay forwarding retains its documented FFmpeg runtime dependency.
