# BobTV 1.4.6 release validation

Published on 2026-11-26 (Asia/Tokyo) with native version `1.4.6+9`.

- Frozen application source: `10b1ffb5a779416d12e698165f157497c45723c5`, pushed to remote main before official compilation.
- Release: https://github.com/sunshaoxuan/clubTivi4bob/releases/tag/v1.4.6
- Seven platforms: Windows x64/ARM64, macOS Intel/Apple Silicon, Android ARM32/ARM64/x64. iOS distribution was unchanged.
- Windows CI: https://github.com/sunshaoxuan/clubTivi4bob/actions/runs/45665188323. Both architecture jobs succeeded and their source provenance matched the frozen commit.

## Application and protocol checks

- 80 focused Flutter tests, 51 AirPlay Python tests and 47 website, diagnostic, release and updater tests passed. The AirPlay suite had no skipped tests.
- Startup normalization preserved results across 22,493 copied channel rows and 21,106 unique inputs.
- Two foreground macOS release-candidate launches with copied channel data reached the channel browser in 4.24 and 5.99 seconds, with zero playback requests and zero fatal errors. These runs excluded restored media playback. They do not establish startup timing for every installation.
- Both macOS variants passed strict signature and native architecture checks, covering 132 native files each. Native helper startup, valid/corrupt updater handoff and isolated observer handoff checks passed.
- Three Android APKs passed package identity, version, ABI, publisher signature and native alignment checks. The ARM32 native-library minimum alignment remains 4 KiB; ARM64/x64 libraries satisfy 16 KiB alignment.
- Live synthetic diagnostic upload/download checks passed on both nodes, including gzip transport, original-JSON digest verification and terminal identifiers. Automatic upload follows the existing diagnostic-sync setting.

## Packaging and publication

- `verify_release_alignment.py` passed for all seven platforms and 15 public assets.
- All 14 entries in `SHA256SUMS.txt` matched. All 15 GitHub asset sizes and SHA-256 digests matched the local publication set before publication.
- Public filenames and display version use `1.4.6`; native update identity and compatibility aliases retain `1.4.6+9`.
- macOS uses the existing ad-hoc application signing profile and publisher-signed update archives. Windows Setup and updater payloads use publisher detached signatures. This release does not introduce Developer ID notarization or Authenticode signing.
- The production mirror completed successfully. All seven update feeds advanced together. Seven localized histories and three static fallback pages were deployed.
- All 29 origin mirror file paths matched their full local SHA-256 digests.
- Public verification passed 116 checks across both nodes: 42 localized pages, 14 update feeds, 58 file range requests (including native-version aliases) and two release indexes. Several relay requests initially returned 502 or timed out; retries succeeded. This establishes endpoint availability during validation, not uninterrupted network reliability.

Physical LG television compatibility and playback on each target device remain outside these package and protocol checks. Casting diagnostics provide evidence for subsequent device-specific analysis.
