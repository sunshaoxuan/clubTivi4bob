# BobTV 资源包 v1

2026-11-20，本地开发实现。取代 mobile-planning-20261120/resource-package-v1.md 的字段草案。

## 使用方式

资源包采用 BobTV 自定义数据结构。服务器保存频道名称、分类、线路、台标和 XMLTV 节目表。用户通过资源包 URL 或文件导入，BobTV 校验后显示摘要，用户确认后应用完整快照。iOS 首次安装为空，无默认频道库或推荐来源；其他现有平台继续使用原分发模式，可用 `BOBTV_USER_SOURCES_ONLY=true` 开启空播放器模式。

`.bobtv` 文件内容为 UTF-8 JSON，HTTP 可返回 `Content-Type: application/json`，可使用 `Content-Encoding: gzip`。文件导入目前只接受未压缩 JSON。协议标识和版本决定解析方式，改扩展名无效。该结构供 BobTV 实现解析，格式本身不提供加密或发布者身份认证。

[完整示例](examples/demo.bobtv) 中使用 `.invalid` 保留域名，需要替换为自己的服务器地址。包只保存数据和资源引用，不携带图片、视频二进制、脚本或可执行模块。

```sh
dart run tools/validate_resource_package.dart my-catalog.json output.bobtv
```

校验工具与应用复用同一解析器，成功后输出数量和规范化文件的 SHA-256。摘要可用于比对文件，不证明发布者身份。服务器可用普通静态文件服务提供 `.bobtv`，无需 BobTV 专用域名。URL 导入默认每 15 分钟在应用运行期间检查一次，并支持电视源管理中的手动刷新。iOS 挂起期间没有固定刷新保证。

## 字段规范

| 路径 | 要求 |
| --- | --- |
| `format` | 必填，固定 `bobtv-resource` |
| `schemaVersion` | 必填，整数 `1`，未知版本拒绝 |
| `id` | 必填，发布者资源集稳定 ID，最多 128 字符，刷新时不得更换 |
| `name` | 必填，资源集显示名称，最多 512 字符 |
| `revision` | 必填，不透明版本字符串，最多 128 字符；用于记录版本，不按字符串比较新旧 |
| `updateUrl` | 可选，HTTP(S) 订阅地址。本地文件导入时显示订阅主机并使用该地址刷新；URL 导入继续使用用户输入的地址 |
| `categories` | 必填数组，1 至 1000 项。每项包含唯一 `id` 和显示名称 `name` |
| `channels` | 必填数组，0 至 10000 项。空数组明确撤回此前线路 |
| `channels[].id` | 必填，在资源集内唯一、稳定，不随名称变化 |
| `channels[].name` | 必填，频道显示名称 |
| `channels[].categoryId` | 必填，引用已声明分类 |
| `channels[].logo` | 可选，HTTP(S) 台标绝对地址；缺失时进入已有台标查找流程 |
| `channels[].routes` | 必填，每频道 1 至 32 条；每项仅含唯一稳定 `id` 和绝对地址 `url` |
| `epgSources` | 可选，最多 32 项，每项仅含唯一稳定 `id` 和 HTTP(S) XMLTV 地址 `url` |
| `channels[].epg` | 可选，含 `sourceId` 与 `channelId`，分别引用节目表源与其中的 XMLTV 频道 ID |

所有 ID 最多 128 字符，其他一般字符串最多 512 字符，URL 最多 4096 字符。字符串非空、去除首尾空白，不接受控制字符。所有对象拒绝未定义字段，缺字段、错误类型、重复 ID、无效引用整包拒绝。扩展字段需要后续协议版本。

分类可使用现有路径，例如 `中国 / 央视`、`国际 / 日本 / 新闻`，也支持自定义分类名称。自定义分类原样展示，频道归属由 `categoryId` 确定。手工单条线路可指定分类，留空复用现有名称识别规则；识别结果需要以实际频道信息为准。

视频线路支持 `http`、`https`、`rtsp`、`rtmp`、`udp`、`rtp`，实际播放能力受平台、网络、编码限制。所有地址拒绝内嵌用户名密码、片段和代码协议。第一版不支持清单自定义 HTTP 请求头、登录流程或相对地址，需要服务器输出客户端可直接读取的资源地址。令牌 URL 按敏感资料保存在本机，不在错误对话框打印。

## 导入与刷新

不同本地订阅使用独立命名空间。同频道多条线路归在一张卡片，两个同名频道采用不同 ID 时保持独立。更新同一线路应保持频道 ID、线路 ID，只修改 URL。应用保留原有收藏、显示与排序选择。手工相同地址重复添加不会再创建条目。

下载、解析、引用校验完成后才写数据库，订阅、线路及 EPG 绑定以事务应用。错误不留下半份新订阅，不替换旧快照。删除或修改来源后，正在下载的旧结果不会重新创建该来源。同一订阅的并发刷新复用任务。失败等待下一次 15 分钟检查，用户可主动重试。

远端移除仍在收藏或收藏列表中的线路时，保留本地引用，名称附加 `[source removed]`，清空播放地址；再次发布同一 ID 时恢复资料。没有收藏引用的缺失线路删除。当前播放会话使用已解析地址，导入流程不主动停止播放器。包撤回节目表来源时停用其自动更新，保留已有缓存和用户手动绑定；删除订阅时清理该订阅拥有的节目表资料。

资源包清单下载直接访问用户输入的服务器，不通过 BobTV 公共资源转发服务。最多 3 次重定向，禁止 HTTPS 降级到 HTTP，不携带自定义认证头或 Cookie。压缩前和解压后各限 8 MiB，总时限 25 秒，连接时限 10 秒，JSON 深度最多 16，总线路最多 30000。文件不解 ZIP。HTTP/局域网能否连接仍受系统权限和网络策略约束。

## 与现有能力的衔接

导入结果进入现有频道、线路和 EPG 数据表。台标有明确地址时由界面按需加载，无台标时调用已有解析服务；节目表有明确引用时建立绑定，其他情况沿用现有自动匹配。导入后异步刷新 EPG，播放沿用原有字幕获取和对齐流程。

本次协议不新增字幕服务器接口、字幕时间轴字段或原生字幕算法。任意第三方线路能否匹配到字幕，取决于现有服务的节目识别与覆盖；协议验收不等同于这些线路均已出现正确字幕。iOS 模拟器端原生识别尚有未解决的错误，沿用 ios-native-adaptation.md 中的记录。

第一版尚未实现 ETag/Last-Modified、签名、加密、发布者登录、刷新取消按钮、后台固定同步。先前草案中对应内容是后续设计项。协议端到端证据见 [本次验收记录](acceptance-20261120.md)。
