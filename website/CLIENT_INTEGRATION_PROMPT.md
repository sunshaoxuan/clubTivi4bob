# BobTV 诊断自动上传代码侧交接 Prompt

请在本仓库的 Windows 客户端实现可由用户主动开启和关闭的诊断自动上传。站点实现和接口契约位于 `website/`，`https://bobtv.briconbric.com/api/v1/logs` 已上线。保持现有日志落盘和轮转行为；不要上传原始 JSONL、播放地址、电视源配置、账号、令牌、路径、异常正文、堆栈、原生崩溃转储或设备唯一标识。

协议：`POST /api/v1/logs`，`Content-Type: application/x-ndjson`，UTF-8 编码，最多 1 MiB 和 5000 行。每行是一个 JSON 对象，必需 `time` 与 `event` 字符串；其余仅允许 `source`、`fatal`、`uptimeSeconds`、`rssBytes`、`maxRssBytes`、`platform`。字段值只能是字符串、数字或布尔值，字符串最长 256 字符，单行最长 4096 字符。服务器返回 `201` 表示保存、`200` 表示同内容已保存，响应的 `id` 为上传内容的 SHA-256；`429` 带 `Retry-After`，`413`、`415`、`422` 是不可重试的输入错误，`5xx` 可稍后重试。接口无客户端密钥，服务端按源站可见地址限流，日志私有保存 14 天。

从现有 `AppDiagnostics` JSONL 日志投影允许字段，保留最近的有限快照。设置页明确说明自动上传目的、字段和 14 天保留期，默认关闭，开启后在启动时与运行期间定时发送，关闭后不再发起请求。网络失败不能影响播放或本地日志。超时、`429` 和 `5xx` 使用有上限的退避；重启后仍可重试最近日志，避免无限堆积。发送相同字节可由服务端去重。Windows 应用关闭期间无需后台常驻。请确认 `https://bobtv.briconbric.com` 是唯一诊断目标，不调用 GitHub 下载接口。

验收：针对隐私字段投影、大小和行数、关闭开关无网络调用、网络失败与限流重试、`200/201` 成功、不可重试响应、重启后补传分别写行为测试。运行项目要求的 `flutter test`、`flutter analyze`，制作新版本 Windows 包后在目标机验证 HTTPS 上传。现有 GitHub 发布包不会因为基础设施上线自动具备这一功能。
